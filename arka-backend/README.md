# АРКА 123 — backend бронирования

Java 17 · Spring Boot 4.1 · PostgreSQL 16 · Flyway · Spring Security + JWT (jjwt 0.13) · Redis (кэш доступности) · Spring Mail + Thymeleaf (письма) · Testcontainers.
Структура и стиль — как в [coworks_project](https://github.com/wolllipp/coworks_project).

## Запуск

```bash
cp .env.example .env            # заполнить пароли и JWT_SECRET (≥ 32 байта)
docker compose up -d            # Postgres :5435, Redis :6380, Mailpit :8025
set -a; . ./.env; set +a
mvn spring-boot:run             # API на http://localhost:8090
```

Первый администратор создаётся при старте из `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

Тесты: `mvn test`. Интеграционные идут на настоящем PostgreSQL в Docker; без Docker они пропускаются.

## Как устроено бронирование

- **Защита от двойной брони — в БД.** `EXCLUDE USING gist (hall_id WITH =, tsrange(...) WITH &&) WHERE (status <> 'CANCELLED')`: две активные брони не пересекутся даже при одновременных запросах. Отменённые не мешают, слот снова свободен. Сервис сначала проверяет пересечение сам, чтобы отдать понятную ошибку, а гонку ловит constraint → `409`.
- **Правила зала (422):** целые часы, с 08:00 до 23:00, минимум 2 ч, не в прошлом, не дальше 90 дней, гостей не больше вместимости формата (лекция 48, общий стол 24, группы 36, свободная 40).
- **Цена — только на сервере.** Выбирается самый выгодный тариф (почасовой / полдня / день), услуги из тарифа бесплатны, кофе-брейк считается за человека. Цена услуг фиксируется в брони.
- **Без регистрации.** Гость бронирует по телефону и получает `code`, по нему смотрит и отменяет бронь. Если запрос пришёл с JWT, бронь привязывается к аккаунту — пользователь берётся из токена, а не из тела запроса.
- **Жизненный цикл:** `PENDING` → `CONFIRMED` (админ) или `CANCELLED`. Гость отменяет онлайн не позднее чем за 24 ч. Неподтверждённая бронь снимается через 24 ч (job раз в 10 мин), чтобы не держать слот.
- **Redis** кэширует занятые часы дня (TTL 10 мин, сброс при создании/отмене). Если Redis недоступен, запросы идут в БД, ошибка кэша только логируется.

## Письма

Гостю — «заявка принята» (с кодом и ссылкой на страницу брони), «подтверждена», «отменена» (с причиной), напоминание за сутки до начала. Администратору (`ADMIN_NOTIFY_EMAIL`) — о каждой новой брони. Email в брони обязателен.

- Шаблоны — `src/main/resources/templates/mail/`, в стиле сайта; таблицы и инлайн-стили для почтовых клиентов.
- Отправка — по событию `BookingEvent` после коммита и в фоне (`@TransactionalEventListener(AFTER_COMMIT)` + `@Async`): если почта недоступна, бронь всё равно сохраняется.
- Локально письма ловит **Mailpit**: http://localhost:8025. Для настоящей отправки — переменные `SMTP_*` и `MAIL_FROM` (пример для Gmail — в `.env.example`).

## API

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| POST | `/api/auth/register` | все | регистрация клиента, сразу токен |
| POST | `/api/auth/login` | все | вход → `{token, role}` |
| GET | `/api/users/me` | вошедший | профиль |
| GET | `/api/catalog` | все | зал, тарифы, услуги, форматы |
| GET | `/api/availability?date=2026-10-15` | все | часовые слоты дня |
| GET | `/api/availability/calendar?from=…&to=…` | все | FREE / PARTIAL / FULL / CLOSED по дням (≤ 62 дня) |
| POST | `/api/bookings/quote` | все | расчёт цены без брони |
| POST | `/api/bookings` | все | создать бронь → `201` + `code` |
| GET | `/api/bookings/{code}` | все | бронь по коду |
| POST | `/api/bookings/{code}/cancel` | все | отмена гостем |
| GET | `/api/bookings/my` | вошедший | мои брони |
| GET | `/api/admin/bookings?date=&status=` | ADMIN | список |
| POST | `/api/admin/bookings/{id}/confirm` | ADMIN | подтвердить |
| POST | `/api/admin/bookings/{id}/cancel` | ADMIN | отменить |

Ошибки всегда в виде `{"error": "..."}`; для валидации добавляется `fields`. Коды: 400 — формат, 401/403 — доступ, 404, 409 — слот занят, 422 — правило зала.
